# 実機テスト計画 — AX8850 上での Irodori-TTS axmodel 検証

> 対象機: **AI Pyramid Pro / Axera AX8850（AX650C, aarch64）= デプロイ先そのもの**。
> 本書は「sim ではなく実機 NPU で何を・どの順で・どう安全に検証するか」の実行計画。
> 観点の背景は `テスト観点.md`、量子化知見は `QUANTIZATION_NOTES.md`、経緯は `FINDINGS.md`。
>
> **基本方針**: 品質の数値（mel_L1）再測定は **x86 sim と冗長なので主目的にしない**。
> 実機でしか得られない価値＝ **(1) sim≡NPU の等価性 / (2) デプロイ配線 / (3) 実聴** に絞り、**安い順にゲート**。
> 各ゲートは fail-loud。NPU は**排他リソース（2プロセス同時で SEGV）**である点が全工程の制約。

## 1. Phase −1: 競合サービスの停止（**全工程の前提・必須**）

NPU を実際に握るのは `pet-album` ではなく **axllm（VLM）と yolo daemon**。現状すでに **axllm + yolo の2プロセスが NPU 使用中**＝SEGV 閾値ぎりぎり。ここに axmodel を足すと3つ目で **SEGV 確実**。加えて axllm は **CMM ~3.3GB**＋System RAM を食い、Ph4 の fp32 CPU ref（~2GB）を OOM させる。

| プロセス | service | NPU | 措置 |
|---|---|---|---|
| `axllm`（Qwen3.5-2B VLM, :8000） | `axllm-serve@Qwen3.5-2B-AX650-GPTQ-Int4-C256-P6K-CTX8K.service` | ◎ +CMM3.3GB | **停止** |
| `ax_yolo_daemon` | `ax-yolo-daemon.service` | ◎ | **停止** |
| `pet-album`（Rust, :8082） | `pet-album.service` | ✗(VLMをHTTP呼出) | **停止**（VLM落ちで500吐くため） |
| `llm-llm` / `llm-sys` | 基盤 service | 不明 | **触らない**（kokoro前例も axllm のみ停止。Ph0で競合が残れば追加調査） |

### 停止（テスト開始前）
```bash
sudo systemctl stop pet-album.service
sudo systemctl stop 'axllm-serve@Qwen3.5-2B-AX650-GPTQ-Int4-C256-P6K-CTX8K.service'
sudo systemctl stop ax-yolo-daemon.service
```

### 解放確認（停止が効いたか・fail-loud ゲート）
```bash
# CMM Cur が ~3.3GB → 数百MB に落ちること
grep -m1 'Cur=' /proc/ax_proc/mem_cmm_info
# System RAM available が回復・swap が空き始めること
free -h
# axllm/yolo プロセスが消えたこと
ps -ef | grep -iE 'axllm|yolo' | grep -v grep
```
→ **CMM が解放されていなければ Ph0 に進まない**（NPU 競合 = SEGV リスクが残る）。

### 復帰（**テスト完了後に必ず実行**）
> ⚠️ **順序が重要**: yolo の `ExecStartPre`(drop-in `vlm-order.conf`) が axllm の :8000 応答を待つため、
> **axllm を先に起動**しないと yolo が timeout で fail する（2026-05-26 実機確認）。順序は **axllm → yolo → pet-album**。
```bash
sudo systemctl start 'axllm-serve@Qwen3.5-2B-AX650-GPTQ-Int4-C256-P6K-CTX8K.service'
# axllm が :8000 で応答するまで待つ（~2-15秒）
for i in $(seq 1 40); do curl -sf http://127.0.0.1:8000/v1/models >/dev/null 2>&1 && break; sleep 1; done
sudo systemctl start ax-yolo-daemon.service
sudo systemctl start pet-album.service
# 復帰後に is-active と :8000 応答を確認。
systemctl is-active pet-album.service ax-yolo-daemon.service \
  'axllm-serve@Qwen3.5-2B-AX650-GPTQ-Int4-C256-P6K-CTX8K.service'
```
> ⚠️ **異常終了・中断時も復帰を忘れない**（pet camera 本来機能が止まったままになる）。長時間ビルド/テストは完走させ、終わったら即復帰。

## 2. テスト・フェーズ（安い順ゲート）

| Ph | 目的 | 使うもの | 合格基準 | コスト | 観点§ |
|---|---|---|---|---|---|
| **0** | 構造/IO 検証 | 3 axmodel を axengine ロード（root） | 各**単一subgraph**・**DiT に latent_mask 入力が生存(53入力)**・x_t T=T_max・dacvae in `(1,32,T)` | 秒 | §1.1/1.3/1.4 |
| **1** | dtype ゲート | `verify_layer_dtypes.py` + quant onnx | **cos→U16 / FC→U16 の coverage を実測 assert** | 分 | §1.2（*DiT/dacvae quant 回収時のみ*。textenc無→skip） |
| **2** | **sim≡NPU 等価**（実機固有価値の核） | 過去 sim 出力 .npy + 同一入力を NPU 実行 | v_pred/wav が **bit一致 or SNR≫**（不一致なら sim 品質結論が無効化） | 分 | （要: build host に sim 出力） |
| **3** | 配線 + 実聴1本 | a_build_cond(cpu)→b_sample(DiT, **lm 53入力対応**)→**dacvae NPU runner(新規)**→wav | step0 axmodel-vs-torch cosine **≥0.85**・wav 破綻なし・**実聴で出荷可否** | 中（num_steps=40, CPU cond） | §3衛生・§5 |
| **4** | フル品質 A/B（**条件付き**） | 短/中/長 × fp32 CPU ref × NPU × mel_L1+実聴 | 短~1.3 / 中~2.2 / 長~2.7 圏内 | 重（CPU ref 生成） | §4（**Ph2 が sim≠NPU の時だけ**／sim 出力が散逸し実機が唯一 arbiter の時） |

### 決定ゲート（最重要・全体を分岐）
**Ph2 の結果で進路が決まる:**
- **NPU ≡ sim** → 既存 sim の mel_L1/実聴がそのまま実機に転送される。**Ph4 はスキップ**、Ph3 の実聴1本で締め。
- **NPU ≠ sim** → sim ベース結論が崩壊。**Ph4 フル A/B に昇格**（実機が唯一の arbiter）。

### Ph0 の具体（前提ゼロ・今すぐ可）
`axengine.InferenceSession` で3モデルをロードし、`get_inputs()/get_outputs()` の name/shape/dtype を出力。
- DiT: 入力数 **53**（latent_mask 含む）か、`x_t` の T が T_max（長, ~201）か。
- latent_mask が prune されず graph input に生存しているか（§1.3）。
- root 実行・`PYTHONPATH=/home/admin-user/.local/lib/python3.10/site-packages`。

### 共通ハーネス衛生（§3, 過去事故防止）
- `AXMODEL_DIR`/`SYNTH_TEXT`/`SYNTH_SEED` 等は **env で渡す**（ハードコード禁止）。
- 起動時に `[config]` print + `compiled.axmodel 存在` assert（**別モデルを測る事故**防止。結果が別ビルドと bit 一致なら routing ミスを疑う）。
- v_pred reshape は `(1,-1,32)` で **T を出力から推論**（T ハードコード禁止）。
- 各実行は **fresh な出力ディレクトリ**（前回結果を上書きしない＝forensic 保全）。

## 4. 実行順（まとめ）

```
[Phase −1] サービス停止 → CMM/RAM 解放確認(ゲート)
   │
[Ph0] 3 axmodel ロード・I/O 構造検証 ── fail → 配線/export を疑い停止
   │ ok
[Ph1] (quant onnx あれば) dtype coverage assert
   │
[Ph2] sim≡NPU 等価 ─┬─ 一致 → Ph4 skip
   │                 └─ 不一致 → Ph4 へ昇格
[Ph3] 実機 a→b→c end-to-end + 実聴1本（配線・最終判定）
   │
[Ph4] (条件付き) 短/中/長 フル品質 A/B
   │
[復帰] サービス再開（**axllm → yolo → pet-album**; yolo は axllm:8000 待ち）+ is-active 確認
```

**推奨スタート**: Phase −1（サービス停止＋解放確認）→ **Ph0**（前提ゼロ・秒で終わる・配線事故を最初に弾く）。並行して §3 のブロッカー①②を build host で確認。
