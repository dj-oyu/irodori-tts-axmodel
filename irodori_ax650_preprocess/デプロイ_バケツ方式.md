# デプロイ設計: 固定長 axmodel の T-バケツ方式

> 課題: axmodel は **固定の潜在長 T（= 音声の長さ）** でコンパイルされる。だが発話ごとに必要な
> T は連続的に変わる。文ごとに axmodel を建てるのは非現実的 → **少数のバケツ**でカバーする設計。

## 1. 制約と実測した「埋め方」挙動

- axmodel 入力 `x_t` は `(1, T, 32)` で T 固定。フレームレート ≈ **25 frame/秒**（T=119 ↔ 4.76秒）。
- duration predictor が text から **T_natural** を予測（短文→小T, 長文→大T）。
- **実測（重要）**: 出力長を `seconds` で T_natural より長く強制すると、**末尾は無音にならず、モデルは
  内容を引き伸ばし/反復して埋める**（「ありがとう。」を 5秒に強制 → 末尾 RMS が頭と同程度のまま）。
  → **「Tを切り上げて末尾の無音をトリム」方式は使えない**（トリムすべき無音が生成されない）。

## 2. 方式A（再 export 不要・即運用可）: 細かいバケツ + duration override

- バケツ集合 `B_1 < B_2 < …` を用意。runtime:
  1. text → duration predictor → `T_natural`
  2. `T_natural` 以上で最小のバケツ `B` を選ぶ
  3. `SamplingRequest(seconds = B/25)` で生成（モデルは少し**ゆっくり**話して B を満たす）
- tempo 変化 = `B / T_natural`。**バケツ間隔を細かく**すれば数%以内＝ほぼ知覚されない。
- トレードオフ: バケツ多 = tempo 歪み小・モデル数多 / バケツ少 = 逆。
- **短い側ほど相対 stretch が大きい**（T=33 を T=64 に＝約2倍）ので、**短い側を細かく**する:
  例 `T = 24,32,40,48,64,80,96,128,160,192,224,256`（必要レンジに応じて調整）。
  - 目安: `B/T_natural ≤ 1.1`（stretch 10%以内）に収まるよう間隔を選ぶ。

## 3. 方式B（より綺麗・要再 export）: latent_mask で無音パディング

- モデルの `forward_with_encoded_conditions(..., latent_mask=...)` は **latent_mask 引数を持つ**
  （現 export では None 固定で未入力化）。
- これを **axmodel の入力として export** すれば、バケツ B フレーム生成しつつ `T_natural` までを有効、
  残りを mask → **末尾を無音にできる** → 単純トリムで T_natural 長の音声を得る。tempo 歪みゼロ。
- **未検証**: mask した余剰フレームが実際に無音になるか要実験（RF が mask 部を無音生成するか）。
  + KV/形状が増えるので再 export・再ビルド・固定長検証が必要。
- 方式A で品質が足りなければ方式B に進む、の順が良い。

## 4. バケツごとの量子化レシピ（品質 vs T より）

実聴の品質曲線（cosU16, §QUANTIZATION_NOTES）:
| T 帯 | 品質 | 推奨レシピ |
|---|---|---|
| 短（T≲40） | fp32 と透明 | **cosU16**（W8A16 + node_cos→U16）。小さく速い。 |
| 中（T~110） | くぐもり（電話品質）・明瞭 | cosU16 で許容なら可。気になれば true-A16 |
| 長（T≳200） | くぐもり＋声質低下 | **true-A16**（全FC入力→U16）= mel 3.68→2.73 で電話品質まで改善（task10検証済, 完全透明には未達） |

- → **短バケツは軽い cosU16、長バケツは重い true-A16（`cosU16 + 全FC→U16`）**、と**バケツごとに別レシピ**で
  建てるのが合理的（長文だけ精度コストを払う）。true-A16 は長文を「muffled+声質低下」→「電話品質」に引き上げる
  （task10: mel_L1 3.68→2.73 単調改善で確定）が透明には届かないので、長文の完全品質が要るなら CPU/QAT も選択肢。
  size 340→344MB（僅少）だが U16 活性化は実機で帯域/レイテンシ増 → **速度コストは実機計測が必要**。
- DACVAE は固定 T=119 のものを別途使う（vocoder は潜在長に追従。バケツごとに DACVAE も要 or 可変長対応を別途検討）。

> 注: 本書は設計方針。各 axmodel は固定長なので、出荷物は「数個のバケツ axmodel + ルーティング」になる。
