# デプロイ設計: 2バリアント（fp32 / 量子化）× 可変長

> 方針（改訂）: length で3バケツに割るのをやめ、**品質軸で2バリアント**に集約する:
> - **fp32 バリアント**（最高品質, CPU, 可変長ネイティブ）
> - **量子化バリアント**（NPU, 高速。true-A16 か、実機 latency 次第で cosU16）
>
> そして**両バリアントとも可変長出力**にしたい。fp32 側は自明（CPU）。量子化側は NPU の固定 shape 制約を
> **最大長 axmodel + latent_mask** で回避して可変長を実現する（本書の中心テーマ）。

## 0. 前提: NPU は固定 shape

- axmodel 入力 `x_t = (1, T, 32)`、T = 潜在長 = 音声の長さ。フレームレート ≈ **25 frame/秒**（T=119 ↔ 4.76秒）。
- NPU は静的タイリングのため**ビルド時に shape 固定**。→ 素朴には「T ごとに別 axmodel」になってしまう。
- これを**1本の最大長モデル + mask**で可変長化するのが狙い（§2）。

## 1. 2 バリアント

| バリアント | 実行 | 品質 | 可変長の出し方 | 用途 |
|---|---|---|---|---|
| **fp32** | CPU(torch) | 最高（劣化なし） | **ネイティブ**（torch は任意長） | 品質最優先 / NPU 非搭載機 / フォールバック |
| **量子化** | NPU(axmodel) | true-A16=電話品質+軽bubbling / cosU16=短文透明・長文くぐもり | **最大長 + latent_mask**（§2） | 高速・省電力が要る本番 |

- 量子化バリアントのレシピは **実機 latency 計測で決める**:
  - **true-A16**（全FC→U16, `kv_*_allfcu16.json`）: 品質↑だが U16 活性化で帯域/レイテンシ↑。
  - **cosU16**（`kv_*_cosu16.json`）: 速いが長文はくぐもる。
  - → 実機で「true-A16 が許容レイテンシに収まるか」を測り、収まれば true-A16、ダメなら cosU16。

## 2. 量子化バリアントの可変長化（核心）

NPU は固定 shape なので「動的 T」は基本不可（AX650 の動的 shape 対応は不確実・要確認だが期待薄）。
**現実解 = 最大長 T_max で1本だけビルドし、latent_mask で実効長を可変にする:**

1. ビルド: `x_t=(1, T_max, 32)`、**latent_mask=(1, T_max)** を**入力に追加**して export・ビルド（T_max は想定最長, 例 256 ↔ 約10秒）。
2. 推論: text → duration predictor → `T_real` → `x_t` の先頭 `T_real` を有効、残りを **latent_mask=0**（パディング扱い）。
3. mask は実効長を決め、有効領域 T_real だけ正しい音声を生成。**末尾 T_max−T_real は捨てる（trim）**。
4. → **1本の axmodel で任意長（≤T_max）を出力**。バケツ不要・tempo 歪みなし。

- 根拠: `forward_with_encoded_conditions(..., latent_mask=...)` は self-attention mask（学習時に可変長バッチを
  パディングする用）。現 export では None 固定で未入力化しているだけ。
- **✅ 検証済（2026-05-25, fp32, `$JOB/test_latent_mask.py`）**: T_real=37 を T_max=61 で生成し latent_mask
  valid=[:37] を毎 step 注入 → **有効領域が直接 T=37 生成と cosine 1.0000＝ビット一致**。latent_mask が実効長を
  完全に支配（seconds=2.44s で T=61 にしてもマスク 37 が勝つ）。余剰領域は**無音でなく garbage(RMS 0.88)だが
  trim で捨てる**ので問題なし。→ **「max-T+mask+trim」で任意長を、保持領域はネイティブ同一品質で出せると確認**。
- 次: **latent_mask を axmodel 入力として export → T_max でビルド**（axmodel 側でも同挙動か sim 検証）。
- ※ コスト: 短文でも常に T_max 計算（NPU は固定 T_max）＝短文の速度メリット無し。
  「1モデルで単純」vs「短文も最大長コスト」のトレードオフ（バケツ方式なら短文は軽い）。

### 2.1 ❌ ダメな代替（実測済）
- **duration override（seconds で長く強制）→ 無音にならず内容を引き伸ばす**（「ありがとう。」5秒強制で末尾も有音）。
  → 「最大長で生成して末尾トリム」を **seconds でやるのは不可**。**latent_mask が必須**。

## 3. DACVAE（ボコーダ段）も同じ構造で可変長化

パイプライン = **DiT(潜在生成) → DACVAE(潜在→波形)**。DACVAE 入力 `z=(1,32,T)` も T が DiT と一致必須。
- 量子化バリアントでは DACVAE も **T_max で1本**ビルドし、DiT と同じ実効長 T_real を渡す（末尾は無音→トリム）。
  DACVAE は conv ボコーダなので**可変長 export 自体は DiT より素直な可能性**（要検証）。
- DACVAE 品質: **W8A8 + 実 calib で実用レベル**（少しホワイトノイズ・音声良好, cos→U16 不要）。
- ビルド注意: precision_analysis ON だと Snake-path の Sub が uint16 overflow で停止 → **analysis off で建てる**。

## 4. 量子化レシピの品質（実聴・mel_L1, 参考）

| T 帯 | mel_L1 | 実聴 | cosU16 | true-A16 |
|---|---|---|---|---|
| 短(T≲40) | 1.33 | fp32 と透明 | ◎ | ◎ |
| 中(T~110) | 2.16 | 電話品質・明瞭 | ○ | ○+ |
| 長(T≳200) | 3.68→2.73 | true-A16 で muffled 解消＋軽 bubbling | △(くぐもり) | ○(電話品質) |

- **true-A16** = 全 245 FC 入力を U16 化（Pulsar2 が FC 前に挿す U16→U8 requant を潰す）。長文 mel 3.68→2.73。
- **PTQ の天井**: 残る bubbling ≒ **S8 重み量子化の床**（Pulsar2 は FC 重みを上げられない）。
  超えるには **AdaRound**（`enable_adaround`, 再学習不要・検証中 task12）→ QAT → or 長文 fp32-CPU。

## 5. 次アクション（優先順）

1. **latent_mask の無音化を fp32 で検証**（最大長で生成し T_real 以降を mask → 無音になるか）。これが可変長化の可否を決める。
2. OK なら **latent_mask 入りで DiT/DACVAE を再 export → T_max 固定でビルド**（量子化バリアント1本化）。
3. **AdaRound が長文 bubbling を減らすか**（task12）→ true-A16 レシピに採用するか決める。
4. **実機 latency 計測**で量子化バリアントを true-A16 / cosU16 のどちらにするか確定。
5. runtime: text→duration→T_real→(fp32-CPU or 量子化-NPU) ルーティング + latent_mask 生成 + 末尾トリム。

> まとめ: 出荷物は **fp32(CPU) と 量子化(NPU, 最大長+mask) の2本**。length バケツは持たず、
> 量子化側は latent_mask で可変長を実現する（要・無音化検証）。
